# 仓库纵览

项目至今共有四个仓库。其中三个各自对应一个开发阶段，彼此不是替代关系，而是同一套设计思路在三个层次上的落地：先把一条筛选链路跑通，再把这条链路抽象成可复用的平台，最后把平台做成可以对外使用的网站。第四个是并行的文档仓库，与这三个阶段之间没有先后顺序，保存的是管线阶段所依赖的各预测工具的评估结论，以及由这些结论推出的管线搭建方案。

四个仓库的正式地址如下，各段正文以这份地址为准。本地路径只作为当前机器上的参考位置，可能因迁移而变动。

| 仓库 | 地址 | 定位 |
| --- | --- | --- |
| iGEM-silk | https://github.com/EarthTan/iGEM-silk | 第一阶段：筛选链路 |
| iGEM-platform | https://github.com/EarthTan/iGEM-platform | 第二阶段：管线与数据 |
| PeptiCraft | https://github.com/EarthTan/PeptiCraft | 第二阶段：网站 |
| iGEM-wiki | https://github.com/EarthTan/iGEM-wiki | 并行：工具评估与管线方案 |

## iGEM-silk · 第一阶段

`EarthTan/iGEM-silk`，本地参考位置 `../iGEM-silk`。这是项目的第一个仓库，目标单一：让 Dry Lab 尽快拿出可以送进 Wet Lab 的候选肽。围绕「丝素蛋白融合功能肽」这一件事从建立起算，16 个微服务（机器学习预测器、结构工具、远程 API 代理）以漏斗式筛选把候选逐轮收紧，安全性作为硬阈值独立淘汰。它交付的是一条能跑的筛选链路和一批候选序列，服务对象是实验室本身，没有界面，也不需要考虑被他人使用。

## iGEM-platform · 第二阶段（管线与数据）

`EarthTan/iGEM-platform`，本地参考位置 `../iGEM-platform`。这一阶段把第一阶段那条针对单一目标的链路抽象为可复用平台：搜索空间扩大到约两千万条 1–30 个残基的短肽，功能方向扩展到抗氧化、抗菌、抗炎、抗黑素四条，骨架蛋白的取值范围扩展到重组胶原蛋白、蚕丝蛋白、弹性蛋白等结构蛋白的专利序列。仓库内完成的事情是数据准备与批量跑分评测——建起肽库与逐工具分数库，对全库跑完 18 个工具的打分预计算，搭起四条筛选管线并把产出落库。它交付的是网站上线所需的一切数据与管线，交付对象是下一阶段的开发工作，而不是最终用户。

这个仓库在 PeptiCraft 工作目录下另有一份副本 `iGEM-platform-main/`，来源是上面那个地址的 `main` 分支，不是独立仓库。两者的差别是刻意的：副本只保留管线运行所需的代码、建表脚本与结果归档，各目录的 README 与专利序列数据包都不在其中，体积也从数百兆压到 291 MB，因此被写入 PeptiCraft 的 `.gitignore`，不随网站仓库入库。文档、代码更新与结果归档都以上面那个地址为准，副本只在需要就地跑管线时使用。

## PeptiCraft · 第二阶段（网站）

`EarthTan/PeptiCraft`，即本仓库，包含 `app/`、`service/`、`resouces/`、`docs/` 与 `publish/`。前端基于 Vite 8 与 React 19，后端是架在 PostgreSQL 之上的 FastAPI 只读服务，数据从远程数据库流向后端再流向浏览器。这一阶段不再产生新的预测结果，只把上一阶段算好的成果库与一个带引导的构建器组织成可用的界面：一份预先算好的筛选成果库，一个负责组装功能肽、骨架蛋白与连接片段的构建器，以及按给药方式所对应的标准对每条候选作出的评估。它交付的是平台本身。

## iGEM-wiki · 工具评估与管线方案

`EarthTan/iGEM-wiki`，本地参考位置 `../wiki`。这个仓库不对应任何开发阶段，保存的是筛选管线的证据依据：管线里用到的每一个预测工具，其来源、训练数据、复现结果与适用范围，以及由这些结论汇总出的四条功能方向的搭建方案。仓库目前只有一次提交，跟踪 340 个文件；模型权重、特征嵌入缓存与全量打分表一类可再生产物由 `.gitignore` 排除，入库的是报告、脚本与图表。

工具部分共 18 个目录，按在管线中的角色可以分成四组。安全与可容忍性这一组是 ToxinPred3（毒性）、HemoPI2（溶血）、MHCflurry（MHC-I 免疫）、NetMHCIIpan（MHC-II 免疫）、AlgPred2（致敏性）与 bepipred3（B 细胞表位）；功能预测这一组是 AnOxPePred 与 AOPxSVM（抗氧化）、Amplify（抗菌）、AIP-ESM2 与 AIP-iFeature-LightGBM（抗炎）、iMFP-LG（抗炎多标签）与 TIPred（抗黑素）；可开发性这一组是 pLM4CPPs（细胞穿膜）、TemStaPro（热稳定性）、SoDoPe（溶解度）与 Aggrescan3D（聚集倾向）；另有一个自研模型 BLSAM-TIP 单占一处，以及一个留空的 SASA 占位目录。各目录的组成不完全一致，绝大多数含一份 `wiki.md`，按根目录 `工具说明(wiki)模板.md` 的四段（基本介绍、来源分析、复现历程、使用评估）写成，多数另有一份篇幅更长的深度评估报告，随附该工具的部署包、复现脚本、打分表与统计图；BepiPred-3.0 的评估直接写在 `bepipred3/bepipred3-result/` 下，没有独立的 `wiki.md`。这些报告共同遵循根目录的 `工具评估标准.md`，该标准分真实可靠性、项目质量、数值解读三个维度，要求事实类信息标注可追溯出处，并要求给出项目贡献、存在缺陷、适用场景与不适用场景的完整评价，而不只是罗列客观事实。

汇总与方案部分由几处构成。根目录的 `README.md` 是平台的项目定位文档，分两阶段叙述——第一阶段的八轮漏斗研究管道作为方法学参考，第二阶段的产品形态作为主体，末尾给出后端要交付的八项能力、数据模型与落地注意事项。`proposal/` 下有五份文档，其中 `管线搭建方案.md` 以 18 个工具的评估结论为依据，逐一判定每个工具在管线中能否充当硬门控、主排序或仅作软信号，并给出共享安全门控加四条方向漏斗的整体结构，另外四份分别对应抗氧化、抗菌、抗炎与抗黑素。`wiki/` 保存 iGEM 官方 Wiki 站点的首页内容，Markdown 与 PDF 各一份；`ai-biology-story/` 是一套以 AI 与蛋白质设计为主题的演讲页面，含时间线网页、演示文稿与讲稿；`plots/` 存放一张覆盖全部工具的得分分布总图。

命名上有一处容易混淆。本仓库根目录的 `DryLab-literature-modeling-discussion.md` 与 `wiki/` 目录分别保存 Dry Lab 的长篇英文说明和 iGEM 官方站点的首页模板；本队参加 iGEM 的 Wiki 正式文稿（大纲、Software、Dry Lab 三份）并不在这个仓库里，而是存放在网站仓库的 `docs/igem-wiki/` 下。名字都与 iGEM 的 Wiki 有关，内容却是两回事。

## 四者之间的关系

三个开发阶段之间，后一个仓库以前一个的产出为输入。网站读的全部是管线阶段落库的成果库，不重跑任何预测器；管线的筛选口径——安全一票否决、每个指标只用一次、权重由数据决定——直接沿用第一阶段定下的规则；第一阶段的候选肽与融合构造则是管线阶段的输入之一。文档仓库与这三个阶段之间不是输入输出的关系，它保存的是这三段工作共同的依据：管线选用哪些工具、每个工具在管线里能担什么角色，判断都出自工具评估；平台对四个功能方向给出的就绪与调研中状态，依据同样来自工具评估。

四个仓库各自保留自己的文档。网站文档体系（`PeptiCraft-文档体系/`）只描述网站阶段；管线阶段的说明随管线仓库自带；项目定位、工具评估与管线方案只存放在文档仓库，网站与管线两个仓库内不重复收录。
