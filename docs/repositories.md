# Repository Overview

The project has had four repositories so far. Three of them each correspond to a development stage; they are not replacements for one another but the same design approach realised at three levels: first get one screening chain running, then abstract that chain into a reusable platform, and finally turn the platform into a website that can be used externally. The fourth is a parallel documentation repository, with no ordering relative to the three stages; it holds the evaluation conclusions for the prediction tools on which the pipeline stage depends, and the pipeline construction plan derived from those conclusions.

The official addresses of the four repositories are as follows, and the text of each section takes this list as authoritative. The local paths serve only as reference locations on the current machine and may change through migration.

| Repository | Address | Role |

| iGEM-silk | https://github.com/EarthTan/iGEM-silk | First stage: screening chain |

## iGEM-silk · First stage

`EarthTan/iGEM-silk`, local reference location `../iGEM-silk`. This is the project's first repository, with a single goal: to let the Dry Lab produce candidate peptides that can be sent to the Wet Lab as quickly as possible. From its establishment it was built around the single matter of "silk fibroin fused to functional peptides"; 16 microservices (machine-learning predictors, structural tools, remote API proxies) narrow the candidates round by round in a funnel-style screen, with safety eliminating independently as a hard threshold. What it delivers is a runnable screening chain and a batch of candidate sequences; its audience is the laboratory itself, it has no interface, and no thought needs to be given to others using it.

## iGEM-platform · Second stage (pipeline and data)

`EarthTan/iGEM-platform`, local reference location `../iGEM-platform`. This stage abstracts the single-goal chain of the first stage into a reusable platform: the search space expands to about twenty million short peptides of 1–30 residues, the functional directions expand to four — antioxidant, antimicrobial, anti-inflammatory, and anti-melanogenic — and the range of scaffold proteins expands to patented sequences of structural proteins such as recombinant collagen, silk protein, and elastin. What is accomplished inside the repository is data preparation and batch scoring evaluation — building the peptide library and the per-tool score library, running the scoring precomputation for all 18 tools over the whole library, and setting up four screening pipelines and writing their outputs to the database. What it delivers is all the data and pipelines the website needs to go live; its audience is the development work of the next stage, not end users.

This repository has another copy under the PeptiCraft working directory, `iGEM-platform-main/`, taken from the `main` branch of the address above; it is not an independent repository. The difference between the two is deliberate: the copy keeps only the code, table-creation scripts, and result archives needed to run the pipeline; the READMEs of the various directories and the patent sequence data package are not in it, and its size is compressed from several hundred megabytes to 291 MB, so it is written into PeptiCraft's `.gitignore` and does not enter the website repository. Documentation, code updates, and result archives all follow the address above; the copy is used only when the pipeline needs to be run in place.

## PeptiCraft · Second stage (website)

`EarthTan/PeptiCraft`, that is, this repository, containing `app/`, `service/`, `resouces/`, `docs/`, and `publish/`. The frontend is based on Vite 8 and React 19, and the backend is a FastAPI read-only service sitting on PostgreSQL, with data flowing from the remote database to the backend and then to the browser. This stage produces no new prediction results; it organises the result library computed in the previous stage and a guided builder into a usable interface: a precomputed screening result library, a builder responsible for assembling functional peptides, scaffold proteins, and linkers, and an assessment of each candidate against the criteria corresponding to its delivery method. What it delivers is the platform itself.

## iGEM-wiki · Tool evaluation and pipeline plan

`EarthTan/iGEM-wiki`, local reference location `../wiki`. This repository does not correspond to any development stage; it holds the evidence basis for the screening pipeline: for every prediction tool used in the pipeline, its source, training data, reproduction results, and scope of application, and the construction plan for the four functional directions summarised from those conclusions. The repository currently has a single commit and tracks 340 files; reproducible artifacts such as model weights, feature embedding caches, and full scoring tables are excluded by `.gitignore`, and what enters the repository is reports, scripts, and figures.

The tools section has 18 directories in all, which by their role in the pipeline fall into four groups. The safety and tolerability group is ToxinPred3 (toxicity), HemoPI2 (hemolysis), MHCflurry (MHC-I immunity), NetMHCIIpan (MHC-II immunity), AlgPred2 (sensitization), and bepipred3 (B-cell epitopes); the function-prediction group is AnOxPePred and AOPxSVM (antioxidant), Amplify (antimicrobial), AIP-ESM2 and AIP-iFeature-LightGBM (anti-inflammatory), iMFP-LG (anti-inflammatory multi-label), and TIPred (anti-melanogenic); the developability group is pLM4CPPs (cell penetration), TemStaPro (thermostability), SoDoPe (solubility), and Aggrescan3D (aggregation propensity); there is also one in-house model, BLSAM-TIP, occupying a place on its own, and a SASA placeholder directory left empty. The directories are not uniform in composition; the great majority contain a `wiki.md`, written following the four sections of the root-directory `工具说明(wiki)模板.md` (basic introduction, source analysis, reproduction history, use assessment), and most have in addition a longer in-depth evaluation report, accompanied by the tool's deployment package, reproduction scripts, scoring tables, and statistical figures; the evaluation of BepiPred-3.0 is written directly under `bepipred3/bepipred3-result/`, with no separate `wiki.md`. These reports all follow the root-directory `工具评估标准.md`, which has three dimensions — true reliability, project quality, and numerical interpretation — requires factual information to be marked with traceable sources, and requires a complete assessment of the project's contribution, existing defects, applicable scenarios, and inapplicable scenarios, rather than merely listing objective facts.

The summary and plan section consists of several parts. The root-directory `README.md` is the platform's project positioning document, narrated in two stages — the eight-round funnel research pipeline of the first stage as a methodological reference, and the product form of the second stage as the main subject, with the eight capabilities the backend must deliver, the data model, and the implementation considerations given at the end. Under `proposal/` there are five documents, of which `管线搭建方案.md` takes the evaluation conclusions for the 18 tools as its basis, deciding one by one whether each tool can serve in the pipeline as a hard gate, a primary ranking, or only a soft signal, and setting out the overall structure of shared safety gates plus four direction funnels; the other four correspond respectively to antioxidant, antimicrobial, anti-inflammatory, and anti-melanogenic. `wiki/` holds the home-page content of the official iGEM Wiki site, one copy in Markdown and one in PDF; `ai-biology-story/` is a set of presentation pages themed on AI and protein design, containing a timeline web page, a slide deck, and a script; `plots/` stores one overall score-distribution figure covering all the tools.

There is one easily confused point in the naming. The root-directory `DryLab-literature-modeling-discussion.md` and the `wiki/` directory of this repository hold, respectively, the long English description of the Dry Lab and the home-page template of the official iGEM site; the team's formal Wiki entries for iGEM (three documents: outline, Software, and Dry Lab) are not in this repository but under `docs/igem-wiki/` in the website repository. The names all relate to the iGEM Wiki, but the contents are two different things.

## How the four relate

Among the three development stages, each later repository takes the output of the earlier one as input. The website reads only the result libraries written to the database in the pipeline stage and reruns no predictor; the pipeline's screening criteria — the hard veto on safety, each metric used only once, weights determined by the data — carry over directly from the rules fixed in the first stage; and the candidate peptides and fusion constructs of the first stage are one of the inputs to the pipeline stage. The documentation repository is not in an input-output relationship with these three stages; it holds the common basis of all three strands of work: which tools the pipeline selects, and what role each tool can play in the pipeline — these judgments all come from the tool evaluation; and the ready and under-investigation states the platform reports for the four functional directions rest on the same tool evaluation.

The four repositories each keep their own documentation. The website documentation set (`PeptiCraft-文档体系/`) describes only the website stage; the pipeline stage's documentation comes with the pipeline repository; project positioning, tool evaluation, and the pipeline plan are stored only in the documentation repository, and are not duplicated in the website and pipeline repositories.
